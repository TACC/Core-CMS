## Standard Features

> [!TIP]
> **All** portals have these features. You may create/edit one test page for all of these.

### Disclosure Markup (`<summary>` and ARIA)

**Tests:** preserve `<summary>` and `aria-*` attributes in Text plugin HTML ([v4.40.0-rc7](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc7)).

1. Log in.
2. Open a page with `?edit`.
3. Add/Edit a Text plugin.
4. Switch to "Source" view and paste:
    ```html
    <details>
    <summary>Abstract</summary>
    <p aria-label="anything">Body text.</p>
    </details>
    ```
5. Save, reopen the plugin, and open "Source" view again.
6. Confirm `<summary>` is still a tag (**not** escaped as `&lt;summary&gt;`).
7. Confirm `aria-*` attributes remain.

### Picture Default Caption

**Tests:** Picture plugin falls back to the filer Image's default caption ([v4.40.0-rc8](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc8)).

1. Log in.
2. In Filer, open an Image and set a **Default caption**.
3. Add a Picture plugin using that image, leave the plugin's own caption empty, and publish.
4. Confirm the rendered `<figcaption>` shows the image's default caption.
5. Set the plugin's own caption text and confirm it overrides the default.
6. Add a child plugin to the Picture plugin (no caption text) and confirm the default caption is **not** shown.

### Bootstrap 4 Alert Colors

> [!NOTE]
> Extends [Bootstrap 4 Alerts](./v4.40.0-rc6.md#bootstrap-4-alerts) (tested in rc6) with the remaining Bootstrap 4 context variants.

**Tests:** `success`, `danger`, `warning`, `info` alert colors ([v4.40.0-rc9](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc9)), test page shown in site navigation ([v4.40.0-rc9](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc9)).

1. Log in.
2. `docker exec core_cms python manage.py create_test_page_alert_style --replace`
3. Confirm the generated test page appears in the site navigation (but the parent `/test/` page does not).
4. Open the generated test page.
5. Confirm all 8 alert variants render with the correct Bootstrap color class.
6. Optionally, add a Bootstrap Alert plugin manually and confirm all 8 contexts appear in the **Context** dropdown.

### TACC Site Card

**Tests:** new Card plugin ([v4.40.0-rc9](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc9)).

1. Log in.
2. `docker exec core_cms python manage.py create_test_page_card_style --replace`
3. Open the generated test page.
4. Confirm Card blocks render `c-card` plus expected skin/layout classes in the DOM.
5. Add a Card plugin manually.
6. Confirm the **Tag Type** field's help text links (article/aside/div to MDN) open in a new tab.

### CMS Plugin Form Alignment

> [!NOTE]
> **Optional.**

**Tests:** multiline field alignment in CMS plugin forms ([v4.40.0-rc9](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc9)).

1. Log in.
2. Open Structure mode and edit a plugin with multiline fields (e.g. Column).
3. Confirm label and control pairs line up in two columns with a consistent gap.

## Deployment/Settings

> [!IMPORTANT]
> Developer/deployment test only — not a portal UI smoke test. Relevant to sites (e.g. Camino) that mount custom Django app settings.

### Custom App Settings → `EXTRA_*` Settings

**Tests:** `settings_custom.py` `EXTRA_*` keys, with legacy `custom_app_settings.py` fallback ([v4.40.0-rc10](https://github.com/TACC/Core-CMS/releases/tag/v4.40.0-rc10)).

1. Mount a `settings_custom.py` with `EXTRA_INSTALLED_APPS` (e.g. blog stack) at `taccsite_cms/settings_custom.py`.
2. Start CMS and confirm blog-related apps are in `INSTALLED_APPS`.
3. Instead, mount a legacy `custom_app_settings.py` with `CUSTOM_APPS` (no `settings_custom.py` `EXTRA_*` keys) and confirm CMS still starts with those apps loaded.
4. Confirm CMS starts when neither legacy nor `EXTRA_*` keys are present.
